# Implementing

## Правила

- Работай только по плану со `Статус: approved`. Нет утверждённого плана — стоп, предложи `/ccaf:plan`.
- Иди по шагам по порядку. После каждого шага отмечай его `- [x]` в файле плана.
- Перед правкой открой соседний код и образец из плана. Повторяй его стиль: структуру пакетов, нейминг, способ маппинга, обработку ошибок, логирование, транзакции, работу с конфигами.
- Конвенции и команды проекта — из `CLAUDE.md`. Новые библиотеки не добавляй без явного шага в плане.
- Миграции — только новые файлы. Применённые миграции не трогай.
- План расходится с реальностью (класса нет, сигнатура другая, решение не работает) — **остановись** и предложи конкретную правку плана. Не импровизируй.
- Ничего лишнего: никакого рефакторинга, переименований, форматирования чужого кода и «улучшений» вне плана.
- Без секретов в коде и конфигах. Не логируй персональные данные и токены.
- После всех шагов — коротко: какие шаги сделаны, какие файлы изменены, что отклонилось от плана.
